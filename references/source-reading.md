# 书籍读取与完整性检查

每次只处理一本书或一篇结构完整的长文。先把原文变成保留章节位置的可检索文本，再开始分析。

## 一、先确认文件

1. 确认本地文件存在，记录文件名、格式和大小。
2. 按文件实际内容判断格式，扩展名只作参考。
3. 读取目录、章节标题和正文样本，确认文字没有乱码。
4. 记录版本信息：作者、译者、出版社或文件内标明的版本。找不到就留空。

文件打不开时，直接说明卡在哪一步。不要根据书名补写内容，也不要用网络摘要代替用户提供的文件。

## 二、按格式读取

### EPUB

- 按 OPF `spine` 的顺序读取正文，避免按压缩包文件名排序。
- 优先从导航文件或 NCX 取得章节标题，再与正文标题核对。
- 去掉脚本、样式、导航菜单和重复页眉，保留正文段落、标题、脚注标记和图片说明。
- 用“章节标题 + 章节内段落序号”定位引文。EPUB 没有稳定页码时，不自行编页码。
- 合并被排版拆开的句子，同时保留自然段边界。

### PDF

- 按页提取文字并保留分页标记，用“PDF 第 X 页”定位引文。
- 有书签或目录时，先取章节清单，再核对对应页段。
- 抽查开头、中间、结尾各两页，检查文字顺序、断行、乱码和漏页。
- 若大部分页面提取结果为空、每页只有少量字符或文字顺序混乱，将文件标记为“需要 OCR”。完成 OCR 后重新抽查三个位置。
- 双栏排版、脚注密集或图片文字较多时，单独检查阅读顺序。

### TXT

- 检测编码，优先按 UTF-8 读取；乱码时再尝试文件能够确认的原编码。
- 根据章节标题模式建立章节边界。无法可靠分章时，用稳定的小节编号，并向用户说明。
- 保留空行，因为空行通常对应自然段。

### Markdown

- 保留标题层级、引用块、脚注和分隔线。
- 代码块、链接列表等非正文内容单独标记，避免混入写作风格判断。
- 章节位置使用标题路径，例如“第二部 / 第 6 章”。

## 三、长书分批处理

长书按章节分批读取，每批结束后把结果写进内部章节表和候选清单。不要依赖一次对话临时记住全书。

每章至少留下四项记录：

```text
章节：第 X 章｜标题
读取状态：完成 / 需重读 / 缺失
讲了什么：一句话
写作动作：一句话
候选位置：开头 / 转折 / 场景 / 原话 / 评论 / 结尾
```

完成一批，再处理下一批。所有章节状态都变成“完成”之后，才能挑卡和归纳文风。

## 四、漏章检查

交付前完成四次核对：

1. **目录对正文**：目录中的每章都能在章节表里找到。
2. **正文对目录**：正文中额外出现的序、后记、附录也有处理记录。
3. **首尾核对**：每章开头和结尾都读取过，避免只靠章节前半段判断。
4. **全书覆盖**：开头、中段、结尾和每个重要阶段都有候选段落；空缺阶段必须回到原文补读。

目录与正文数量对不上时，先检查合章、分章、无标题章节和附录。无法解释的缺口要告诉用户，并暂停最终归纳。

## 五、引文定位

- PDF：文件名｜PDF 第 X 页｜章节名｜谁说的
- EPUB：文件名｜章节名｜段落序号｜谁说的
- TXT：文件名｜小节名或稳定编号｜谁说的
- Markdown：文件名｜标题路径｜谁说的

每张卡都从已经核对过的位置取原文。引文与后台记录逐字核对，省略内容用省略号标明。

## 六、允许交付的条件

同时满足下面四条，才进入卡片和画板制作：

- 全部章节都有读取状态；
- 没有无法解释的章节缺口；
- 开头、中段、结尾均已抽查；
- 引文能稳定定位到原文件。

条件暂时未满足时，交付读取报告：已读到哪里、缺什么、用户需要换文件还是补 OCR。
