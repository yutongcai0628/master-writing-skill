# 练一下

## 占多少

**整份文档的 10%**（篇幅表在 [`feishu-course-template.md`](feishu-course-template.md)，那里是唯一的出处）。它负责让用户当场动一次手，不承担教学。

## 要有哪几样

1. 一份素材（用户不用回去翻原书就能写）
2. **一道题**，8–15 分钟能写完
3. 3–4 条自己对答案的检查项
4. 一个交作业的入口

**只出一道题。** 出两道，用户一道也不会做。

## 素材怎么给

用表格装，左列标明这是哪一类素材，右列是内容：

| 素材类型 | 内容 |
|---|---|
| 本人原话 | …… |
| 旁人说的 | …… |
| 立场相反的人说的 | …… |
| 能查证的数字 | …… |
| 现场细节 | …… |

素材只提供事实，**判断留给用户**。至少给够四类，这样用户才有东西可轮换。

## 题目怎么出

题干控制在五行以内，说清三件事：写多少字、必须做到哪几件事、哪几个词不许用。

按用户水平调难度（见 SKILL.md 的水平表）：

| 水平 | 题目形态 |
|---|---|
| 新手 | 一个动作，8 分钟。比如「把这段里所有的『是、有、在』换成具体动词」 |
| 不稳定 | 两个动作，15 分钟 |
| 有稳定产出 | 完整片段，带限制条件。比如禁用某几个词 |

**加一条禁用词**可以让用户绕开第一反应。第一反应通常也是最容易写成套路的地方。

## 交作业的入口

用飞书原生待办，别画文本方框：

```xml
<checkbox done="false">写完了，请读一下给我反馈</checkbox>
```

## 反馈

用户交了之后按 [`scoring-rubric.md`](scoring-rubric.md) 改。四步：先指出哪个写作动作已经用对，再挑一处最值得提升的，只改一句作示范，最后回到相关拆句卡，看作者在类似位置怎样处理。

批改后问用户要不要继续。用户愿意时，再针对刚才指出的问题给一道短题。
